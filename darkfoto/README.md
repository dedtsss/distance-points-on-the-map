# DarkFoto MVP

Standalone Android-first photo batch app. Run `npm ci`, `npm test`, and `npm run android:sync`; CI builds an unsigned release APK. `npm run dev` serves a browser version for local checks. The implementation target is 0.4.0 (versionCode 14); the permanent signing process remains in [SIGNING.md](SIGNING.md).

Select individual photos or an Android folder. Android's document picker copies each selected photo into a private bounded cache file and gives the WebView a Capacitor local file URL; full photo bytes never traverse the JS plugin bridge. Browser EXIF GPS takes priority. Android uses bundled offline ML Kit on a bounded native stamp crop; Tesseract receives only a small prepared crop as a four-second fallback. The donor exact conflict-cover logic divides valid points into Основные and Резерв at 25 m. Photos without confident coordinates or a confirmed visible index go to Требует проверки with a specific reason and cannot enter distance calculations. Android TXT uses the system save/share UI. TXT blocks retain the donor field order.

Choose local processing, Onion or NinjaBox explicitly. Onion requires a 56-character `.onion` service address and working Tor/Orbot routing. NinjaBox requires a public HTTPS DarkFoto relay ending in `/v1/ninjabox`; the standalone relay source is in `relay/worker.js` and reuses the donor provider. Set `VITE_NINJABOX_RELAY_URL` at build time to prefill its address. The routes never fall back to one another. Only verified sanitized JPEG copies are sent; original names, files and raw metadata stay local. The relay does not use D1, accounts or embedded credentials.

The built-in NinjaBox relay URL can be overridden with the GitHub Actions variable `DARKFOTO_NINJABOX_RELAY_URL` at build time. The separate NinjaBox smoke uploads a metadata-cleaned representative JPEG from a browser origin and requires a per-photo `/i/` viewer link. Publication shows cleanup and upload separately, with a 35-second cleanup and 90-second client upload bound. Android reuses its cached selected photo during publication. No relay or Onion service is deployed by this source change.

An unfinished Android publication stores a bounded selected-photo copy and result manifest in app-private storage. Reopening restores completed links and resumes only pending or failed photos; The current session retains these temporary copies after publication for membership edits and re-publication; choosing a new session clears them. Outgoing JPEG names use a recognized index or ordered `NN01.jpg` fallback, while original local filenames stay on the device.

Results offer TXT save/share, ordered per-photo block copy, and GPX waypoint save/share through Android's system UI. Bulk copy sends separate clipboard events 220 ms apart; keyboard history retention varies by keyboard, so each valid row also has an individual copy action. GPX includes valid Main and Reserve points only.

The About / Update tab reads the installed package version, checks public DarkFoto GitHub Releases, and offers newer release APKs with a published SHA-256 digest. Android DownloadManager keeps APK downloads running while the app is backgrounded; the About tab recovers progress and retains a verified APK for repeated install attempts. Before Android's installer opens, native code checks package ID, increasing versionCode, release SHA-256, and the pinned permanent signer certificate. It never uses the production signing key.

The bundled OCR worker, WASM, and English model allow local OCR without a CDN. The model comes from [tesseract-ocr/tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast/blob/main/eng.traineddata). See [OCR-EVIDENCE.md](OCR-EVIDENCE.md) for the measured fixture corpus and offline engine choice. CI exercises native JPEG cache copying, WebView decode/crop/OCR and a three-photo batch in an Android emulator. Physical Android photo selection, EXIF orientation, installer handoff and Orbot still need owner field checks.

Member thumbnails retain full-screen preview and offer Ionic actions to move or remove one photo. A searchable chooser moves into an existing point without merging point identities. The final removal leaves a recoverable removed-point placeholder; an emptied move source can recover its photo from the destination. Individual removal offers immediate undo until the next membership operation or publication. Добавить фото recognizes only the new selection, uses the accepted grouping evidence to attach to exactly one active point, and leaves ambiguous matches separate. Edits invalidate only affected publications; stale URLs stay out of TXT/copy until those points are re-published. Every current public link has separate Открыть and Копировать URL actions.
