# Codex workflow

## Цель

Сделать разработку без постоянного ручного копирования логов, ошибок и кода между ChatGPT, GitHub, Codex и Cloudflare.

## Основной порядок работы

1. ChatGPT формулирует задачу и создаёт GitHub issue.
2. Пользователь один раз запускает Codex по этой issue.
3. Codex работает внутри GitHub-репозитория:
   - читает задачу;
   - смотрит файлы;
   - правит код;
   - проверяет GitHub Actions;
   - читает логи при падении;
   - создаёт PR или коммит;
   - пишет отчёт.
4. ChatGPT проверяет результат:
   - issue;
   - PR;
   - изменённые файлы;
   - статус сборки;
   - следующий технический шаг.
5. Пользователь вмешивается только если нужно подтвердить доступ, добавить внешний ключ/секрет или проверить результат на реальном устройстве.

## Что не должен делать пользователь

Пользователь не должен вручную переносить:

- длинные логи GitHub Actions;
- большие куски кода;
- повторяющиеся ошибки сборки;
- файлы из GitHub в Cloudflare, если есть автодеплой.

## Формат issue для Codex

Каждая задача должна содержать:

- контекст проекта;
- что именно сломано или что нужно добавить;
- список важных файлов;
- что нельзя менять без необходимости;
- критерии готовности;
- требование проверить сборку/деплой;
- требование самому читать доступные GitHub Actions logs;
- финальный отчёт: изменённые файлы, результат проверки, следующий шаг.
